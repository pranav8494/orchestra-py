Challenge 1 — Multi-Agent Task Solver

The brief, and what shipped

Accept a high-level business request in plain language — e.g. “Summarize the last 3 quarters’ financial trends and create a chart” — then use multiple specialized AI agents to break down the task, execute subtasks, and return a final structured result.

Solo. 24 hours.

Core requirements — all five

#RequiredShipped asStatus
1 Input — business request in text orchestra run "<request>" ✓
2 Planning — system decides which agents and what each does One planner call → a validated DAG. Plan shape follows the request ✓
3 Execution — agents complete tasks and share results 3 specialized workers, real tools, concurrent under one TaskGroup ✓
4 Aggregation — combine into a final answer Aggregator → executive summary, sourced figures, chart ✓
5 Visibility — progress per agent Rich dashboard on stderr, driven by an event broker ✓

Expectations

ExpectedShipped asStatus
Clear role definitions (specialized prompts) prompts/, one module per agent, never inline ✓
Context sharing between agents Typed ledger; each worker gets only its slice ✓
Tool usage (Python executor, search API) run_python (subprocess), search (Tavily + offline corpus), fetch_data ✓
Avoid hallucination and repetition Pointer-backed figures; repetition detector; turn/token/step budgets ✓
High marks — handle ambiguity by asking clarifying questions Planner returns clarify instead of a plan. One round, ≤3 questions ✓

Stretch goals

GoalStatusNote
Live conversation mid-execution ✓ Press i — run pauses between steps, orchestrator replans what is left
Multi-turn refinement after output ✗ Timeboxed and cut. Filed as #13

Bottom line

All five core requirements, every expectation including the high-marks one, and one of two stretch goals. 651 tests, offline.

Architecture

Architecture, and why this shape

Pattern choice

Four patterns evaluated. This is A — centralized orchestrator over a typed shared ledger.

RejectedWhy not
B — peer-to-peer handoffs A→B→A loops are easy to write, hard to detect. No natural place to draw top-level progress
C — blackboard Needs Redis or a database. Non-deterministic ordering. Infrastructure for a problem we don’t have
D — hierarchical sub-teams Prompt-chaining latency for three roles
Why A
One place to enforce the retry cap, the step budget, the clarification round and the figure-sourcing rule.
What it costs
The planner is a single point of failure. One bad plan, one bad run. No peer correction — the only recovery is a human pressing i.

Three decisions that carry the design

DecisionReason
Ledger is typed, not a dict It sits on three trust boundaries: model output flows in, it is serialised into prompts, the CLI reads it for the exit code. Plan runs Kahn’s algorithm in a validator — a cycle the model invented is rejected at construction, not found later as a deadlock
Artifacts are pointers, never blobs State is serialised into a prompt every step; an inlined payload is billed on every later call. And the pointer doubles as the citation
The provider is a port One Protocol. The whole app runs against FakeProvider with no patching — which is why 651 tests cross the real CLI boundary offline

The guard that makes the output trustworthy

state.backed_figures() keeps only figures whose source is an artifact this run produced. Anything else is dropped before the report is written.

A figure citing an artifact nobody wrote is invention, whichever agent states it.

Layer rule, enforced at commit time: cli/ → app.py → agents/ → {core/, tools/, providers/}. core/ imports nothing upward and no vendor SDK.

Execution

One prompt, end to end

uv run orchestra run "Summarize the last 3 quarters financial trends and create a chart"

Walkthrough

StepWhat happens
1. Catalogue data/ is probed at startup — headers, JSON keys, first line of text. Produces the roster of what the team can actually obtain
2. Plan One call. Request + roster in. Out comes either a DAG or a clarifying question
3. Ambiguity “Make a chart of performance” names no measure → clarify, offering only measures a file holds. One round, enforced by the ledger, not a counter. Piped stdin gets no prompt — it plans against the most reasonable reading rather than hanging
4. Execute Ready set → semaphore(4) → one TaskGroup. Completion-driven: the scheduler rescans on every completion, so no step waits for its level’s slowest
5. Work Each worker gets its subtask, its declared inputs as pointers, and nothing else. It writes its payload to disk and returns artifact:<name>
6. Aggregate Report synthesised from artifact previews. Unsourced figures dropped
7. Out Report on stdout; dashboard on stderr, so the output stays pipeable. Exit code says what happened

The plan shape follows the request

PromptPlan
“…trends and create a chart” 3 steps, sequential
“…against industry benchmarks and chart the trend” 4–5 steps, two retrievals with no edge between them — they run concurrently
“Summarize the revenue trend in one paragraph” 2 steps, no chart — nothing asked for one
“Make a chart of performance” No plan. It asks first

Asserted offline on plan shape, and live against the real model. The fan-out overlap is asserted on the event stream: the second subtask_started lands before either subtask_completed.

Bounds, all defaults

  • 6 turns
  • 60,000 tokens per subtask
  • 3 attempts per step
  • 15 steps per run
  • 4 concurrent
  • 1 clarification round
  • repetition trips at 5 repeats in a window of 10

Failure modes

What breaks, and what it takes to fix

Ordered by what I would fix first. All four filed issues, plus two found by the live pass.

IDWhat’s wrongFixSize
#36 The three knobs an operator most needs — step cap, executor clock, provider timeout — never reach Config. build_orchestra passes max_concurrency and subtask_attempts and stops there 3 fields, 3 wires One sitting
D1 A figure can cite an artifact holding only some of its numbers. The report stated "$5.76M → $7.02M (+21.8%)" sourced to the retrieval artifact. The revenues are in it; the +21.8% was computed by the analytics step. The guard checks the pointer names a run artifact — not that the artifact contains the number Verify the value appears in the cited payload, or require a compound figure to cite the downstream artifact Small
#40 Tool output is stored and re-sent whole every turn. Only run_python is capped. search snippets have no cap at all Cap in the tool loop; elide stale results past N turns Small, real behavioural risk
#33 Visualization drops interior categories — a three-quarter request charted Q2 and Q4, title still claiming Q2–Q4. Root cause: the worker charts from an 800-char preview and re-types every value as model output Feed it the artifact whole; assert value count equals category count before rendering Moderate
#31 On a non-UTF-8 stdout the ASCII chart’s █ raises UnicodeEncodeError — the finished report is discarded, exit 1 Pick the glyph from console.encoding; encode with errors="replace" Small

D1 is the one that matters. It is the claim the README leads with, and only the live pass caught it — the offline suite was always going to be green.

Which points at the real gap

Three things get called “testing”. Two are covered.

QuestionCovered byStatus
Does it run? 651 offline tests — plan shapes, retries, budgets, exit codes, terminal restore ✓
Is it traceable? The pointer guard D1
Is it right? — ✗

The offline suite scripts a fake provider to produce a known answer, then checks the plumbing carried it through. It cannot fail because a model reasoned badly — no model reasoned.

The lightweight fix: grade the JSON, in tiers

-o json is already a published contract, so the system is machine-gradeable today. A golden set of hand-derived question/answer pairs over the same bundled corpus, run nightly:

TierAssertsCost
1The number, within tolerancefree
2 It cites an artifact of the right role — this is the D1 regression testfree
3 The chart contains every category its title claims — the assertion #33 neededfree
4 LLM judge, free text only — binary criteria against a reference answer, never a 1–10 score~1 call

For questions that reason over documents (project_timeline.md is prose), grade on two binary measures, not wording: key-fact recall — does it contain the milestone, the date, the figure — and a contradiction check, which is fatal rather than deducted. Inventing a cause is the exact failure the pointer guard exists to prevent; it must not be averaged away.

Two archetypes worth building first: the unanswerable question, where the correct answer is “the data does not say”, and the distractor — “did the 2025 hiring wave drive the Q2 cost increase?” The wave is real, dated 2025-07-22, affecting Q3. The plausible answer is wrong on the date. That one separates reading from pattern-matching.

Non-determinism: run 3, pass on 2 — except provenance and contradiction, which must hold every time.

Scale

How it scales, and where it breaks first

data/ is 7 files and 28 kB. Every number here is derived from a constant in the repo, not measured. That is itself a finding.

The first thing that breaks is not the data volume

It’s the catalogue. At 13 files.

MAX_LISTED_DATASETS = 12. The catalogue is composed into two places — the retrieval tool’s description and the planner’s roster. Past 12 it emits “…and 3 more not listed here”.

The 13th file exists and would fetch fine. But its name appears in no prompt, and the unknown-name error is capped identically, so the model cannot discover it by failing either.

The roster closes with the clause that stops the model inventing data: “nothing beyond those files and their own columns.” At 13 files that clause becomes actively wrong. It tells the planner that data we hold does not exist.

The failure isn’t a stack trace. It’s a well-worded refusal to answer a question we had the data for.

Fix Moderate

Search the catalogue instead of reciting it — find_dataset(query). One tool, one extra turn, and the anti-invention clause has to be re-derived from the search result.

Then, in order

TriggerBreaksWhy
~3 files near 16 kB in one subtask The token budget Tool output re-sent whole each turn (#40). 16 kB ≈ 4k tokens; three resident across a 6-turn loop ≈ the whole 60k budget. The step fails and its results are lost
~20–40 data points The chart Charted from an 800-char preview; past that the model fills the gap (#33)
2 runs in the same second The audit trail Run directory is second-granular. Nothing is overwritten — the reports stay correct — but two runs’ artifacts mix
~8–10 subtasks The step cap 15 counts every dispatch including retries, and it isn’t configurable (#36)
Hundreds of MB The 15 s executor clock Each file is copied twice before pandas reads it a third time
~10 concurrent runs The box One process per run, no shared token bucket, no cost meter

Three axes, three different failure characters

AxisCharacter
More / bigger files Silent and semantic. The catalogue break is a confident refusal, not an error. This is the axis that lies to you
More concurrent runs Operational and loud. No shared state to corrupt — because there is no shared state, which is also why there’s no backpressure and no resume
Longer plans Structural. Step 9 has no idea what step 2 concluded unless the planner drew an edge. In a 3-step plan that’s context hygiene. In a 12-step plan it’s amnesia. And the DAG is drawn in one call up front — no re-decomposition

What doesn’t break: the aggregator reads file heads, not files — a 10 GB artifact costs what a 1 kB one does. The parts designed to be bounded are bounded.

Everything that breaks, breaks at a prompt boundary. That’s where the scaling debt was put, on purpose.

The point of view

Good for
≤12 datasets, files in kB–MB, plans of 3–10 steps, one operator, and a hard requirement that every number be traceable.
Would not use for
Answers that live in a warehouse; untrusted input — run_python is isolation, not a sandbox; anything needing durable resume or run history.

At that N, keep three things and replace one

KeepReplace
The validated DAG — porting the engine to a workflow runtime is a port, not a redesign Retrieval becomes a query, not a file. The model writes SQL with a LIMIT; the tool returns a bounded result set plus a pointer to the full one. Moves the ceiling three orders of magnitude and deletes two breakpoints outright
The pointer-and-citation model The ledger becomes durable — one row per transition. Resume, replay and audit come with it
The provider port run_python becomes a container per call. The one place this design cannot be tuned into safety

Glossary

Every abbreviation used in this deck, and what it means here specifically.

Abbreviations

AI
Artificial intelligence.
API
Application programming interface. Here: the model endpoint the agents call, authorised by ANTHROPIC_API_KEY, and the optional search API.
ASCII
American Standard Code for Information Interchange — the 128-character text encoding. The ASCII chart is the bar chart drawn in plain text so it can appear inside the terminal report.
CI
Continuous integration — the automated build-and-test run on every change. A CI run has no human at the terminal, so it never gets a clarifying question.
CLI
Command-line interface. The orchestra run … terminal program, chosen over a web front end to spend the budget on orchestration.
DAG
Directed acyclic graph. The plan: subtasks as nodes, dependencies as edges, and no cycles — so a valid execution order always exists. A cycle the model invents is rejected when the plan is constructed.
HTML
HyperText Markup Language. Each chart is written as a standalone .html file that opens in a browser.
JSON
JavaScript Object Notation. Both the structured output format (-o json) and the on-disk format of most artifacts.
kB · MB · GB
Kilobyte, megabyte, gigabyte — file sizes. 16 kB is the threshold above which a fetched file is passed on as a pointer instead of inline rows.
LLM
Large language model. The model that plans, analyses and writes the summary. An LLM judge is a second model call used to grade free text against fixed criteria.
SDK
Software development kit — the vendor's client library. Quarantined in providers/, so no other layer imports it.
SIGINT
Signal interrupt — the signal sent by Ctrl-C. The run cancels its tasks, restores the terminal and exits 130.
SQL
Structured Query Language. Not used today; proposed on slide 5 so retrieval returns a bounded result set rather than a whole file.
TTY
Teletypewriter, now simply "terminal" — an interactive session with a human at it. Clarifying questions and the i interrupt both require one; piped input has none.
UTF-8
Unicode Transformation Format, 8-bit — the default text encoding. On a non-UTF-8 output stream the chart's block characters raise an error, which is issue #31.
stdout · stderr
Standard output and standard error, the two text streams a program writes to. The report goes to stdout and the live dashboard to stderr, so the output stays pipeable.

Identifiers

#13 #31 #33
#36 #40
Issue numbers in the project's tracker. #13 is the cut stretch goal; the other four are the open defects on slide 4.
D1 · O1
Defect 1 and observation 1 from the recorded test results. D1 is the figure citing an artifact that holds only some of its numbers; O1 is a redirected output stream being treated as a terminal.

Terms of art

artifact
A payload written to disk by a step — a dataset, an analysis or a chart. Referred to everywhere by an artifact:<name> pointer rather than by its contents.
ledger
The single typed state object for a run: the plan, the artifact pointers, the events and the answers to clarifying questions.
roster
The list of datasets the retrieval tools can actually obtain, composed into the planner's prompt so it plans only against data the team holds.
provenance
Whether a stated number can be traced to the artifact that produced it. Distinct from correctness: a number can be correctly sourced and still answer the wrong question.
fan-out
Two or more steps with no dependency between them running at the same time.
2025Q2
Q2 · Q3 · Q4
Fiscal quarter notation — 2025Q2 is the second quarter of 2025, and a bare Q3 means the third quarter of the year under discussion. The bundled figures span 2024Q1 to 2025Q4.
