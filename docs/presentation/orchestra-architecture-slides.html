Architecture

Four decisions. Nothing novel — but each was chosen against a named alternative, and each paid for itself inside the day.

Layering

Dependencies point one way

Decisions

Four choices, and what each cost

DecisionRejected alternativeBoughtCost
One-way dependency rule A conventional layered app where anything imports anything and discipline is a review comment A core reusable behind any front end — or another language’s front end. Machine-enforced, so it cannot quietly rot Indirection a prototype could technically skip
Ports and adapters Calling the vendor client directly from agent code A second model vendor is one adapter and one line. The whole suite runs against a fake implementation of one interface Today there is one vendor and no runtime switch — the seam is proven by tests, not by a second implementation
One composition root Globals, singletons, or a service locator The system’s whole wiring reads in one screen. Substituting any part needs no patching framework Every dependency passed explicitly
Pointer ledger Passing results between agents directly Context cost scales with steps, not data size. Traceability falls out free — a citation check is a set-membership test Invalidation is manual: re-running a step means walking the graph and clearing everything downstream

The load-bearing decision

Pointers, never payloads

Shared state is fed back into a model on every call. Inline a large file once and you pay for it on every later call.

So the ledger carries references; payloads live in an artifact store, and whoever needs content re-reads it — bounded by a preview limit or an inline threshold.

Stated precisely: no agent hands another a payload. That is a narrower claim than “agents only ever see pointers”, and it is the one the code actually supports.

What it bought

Context cost grows with the number of steps, not the size of the data. A 10 GB artifact costs what a 1 kB one does at synthesis time.

What it cost — staleness

A pointer outlives the validity of what it points at. Re-running a step means walking the graph downstream and invalidating by hand.

What it cost — lossy previews

Summarisers see a bounded preview, so what goes at the top of an artifact became load-bearing. A contract held together by a comment is a fragile contract.

Control flow

Two branches worth watching

The obvious design

Wave by wave

Compute the graph’s levels. Run all of level 0. Wait for all of them. Then start level 1.

The cost

Every step waits for the slowest peer in its level. A two-second data fetch and a thirty-second search sit in the same level — so the fetch’s dependent idles for twenty-eight seconds with nothing to wait for.

What I built

Completion-driven

One scope spans the whole run. Readiness is re-checked on every completion, not at level boundaries.

The property

Every step starts the moment its own dependencies are done — never when its level is done.

And a failed step ends a step, not the run

Its dependents never become ready; everything independent still completes. Partial results beat no results, and the exit code carries the verdict so a caller need not parse text.

Roles

Three specialists, and what each may not do

  • Retrieval finds and loads raw data. It may not analyse, and it may not draw.
  • Analysis computes over what an earlier step retrieved — by writing and running real code. It may not fetch its own data, so a reported figure always traces to a step the plan ordered.
  • Visualization turns computed figures into a chart. It may not fetch, and it may not compute the figures it plots.
  • A role that can fetch, compute and draw is not a team — it is one agent with a longer prompt.

Why the restrictions are the design

Each “may not” removes a way for the report to cite something the plan never ordered. The constraint is what makes provenance possible — not the citation check downstream of it.

Where it leaks

Visualization has no tool to open an artifact, so it charts from a bounded preview and re-types every value. That is the root cause of a known defect where a chart quietly dropped a middle data point.

Designing for failure

Every failure mode I could name got code and a default — not a promise. The framing matters more than the list.

At the tool boundary

Failures are data

A bad argument, a missing file, a timeout, even a tool name that does not exist — all come back as readable content saying what was wrong and what would work.

Why

The model’s next turn is its own retry. Throwing would unwind the agent loop and deny it that. Only a ceiling being hit is allowed to end a step.

Three outcomes, not two

A lookup that ran and matched nothing is neither a failure nor a result. Marking it an error invites a pointless retry; marking it a result lets “nothing found” count as data retrieved.

At the process boundary

A typed taxonomy

Configuration problem, vendor problem, task failure, interrupted — each is its own class carrying its own exit code.

Why

A caller distinguishes retry the provider from the task did not succeed without reading a message. Rendering happens once, at that boundary — errors never format themselves.

Degrade, never lose

If synthesis fails, the run still reports what it produced. The artifacts are already paid for; empty output would waste them.

What it stops

Accidental network calls. Secrets reaching generated code. A loop that never ends. State bleeding between calls. Output flooding the prompt. A stray exit killing the orchestrator.

What it does not stop

Reading any file the process’s user can read — including a credentials file on disk. Executing a binary by absolute path. Escaping the kill group. Exhausting memory.

The claim I will not overstate

Isolation, not a sandbox

  • Analysis is open-ended, so a fixed set of typed helpers answers only the questions enumerated in advance. Generated code is the honest answer.
  • Running it in a separate short-lived process is what makes that affordable: a wall clock can kill it, and a runaway loop cannot take the orchestrator with it.
  • That raises the cost of an accident. It does not contain an adversary. The code runs as my user, on my filesystem.
  • Real containment is a separate user, a container or micro-VM per call, and resource limits — infrastructure, not a 24-hour decision.
05

Correctness

The part I am weakest on, stated before anyone has to ask.

The honest limit

Three things get called “testing”. Two are covered.

Does it run? covered

653 offline tests — plan shapes, retries, budgets, exit codes, cancellation, terminal restore. The real application end to end.

Is it traceable? partly

The citation guard verifies the cited artifact exists and was produced by this run — not that it contains the number. A figure blending a retrieved value with a derived one passes while citing a source supporting half of it.

Is it right? not covered

Nothing checks the analysis is correct. The system only asserts that code ran and printed something.

Why the suite cannot catch it

The offline suite scripts a fake model to produce a known answer, then checks the plumbing carried it through. It cannot fail because a model reasoned badly — no model reasoned.

The framing

Correctness for an agent is a distribution, not an assertion. So the harness reports a pass rate across repeated runs with a numeric tolerance, gates only on the deterministic tiers, and treats a model-as-judge as a report — never a gate.

Why it is cheap to add

The structured output format is already a published contract, so the system is machine-gradeable today without changing a line of it.

Scale

Every threshold that follows is derived from a constant in the design, not measured. That is itself a finding.

The first thing that breaks

Not the data volume. The catalogue — at thirteen files.

The list of available datasets is capped and composed into two prompts: the retrieval tool’s description, and the planner’s roster of what the team can obtain. Past the cap it emits “…and 3 more not listed here”. The thirteenth file exists and would load fine — but its name appears in no prompt, and the unknown-name error is capped identically, so the model cannot discover it by failing either.

The roster closes with the clause that stops the model inventing data: nothing beyond those files and their own columns. At thirteen files that clause becomes actively wrong — it tells the planner that data we hold does not exist.

The failure is not a stack trace. It is a well-worded refusal to answer a question we had the data for.

Each threshold, and what it takes down

TriggerBreaksWhy

Three axes

Three different failure characters

More or bigger files — silent and semantic

The catalogue break is a confident refusal, not an error. This is the axis that lies to you.

More concurrent runs — operational and loud

No shared state to corrupt, because there is no shared state — which is also why there is no backpressure and no resume.

Longer plans — structural

Step 9 has no idea what step 2 concluded unless the planner drew an edge. At three steps that is context hygiene; at twelve it is amnesia. And the graph is drawn in one call up front — there is no re-decomposition.

What does not break

Synthesis reads file heads, not files — a 10 GB artifact costs what a 1 kB one does. The parts designed to be bounded are bounded.

The pattern underneath

Everything that breaks, breaks at a prompt boundary. That is where the scaling debt was put — on purpose. Nothing breaks in the scheduler, the ledger, or the store.

Which tells you where to spend

The fix is not more machinery. It is replacing recitation with retrieval: search the catalogue instead of listing it, profile a dataset instead of previewing its first characters.

The point of view

What this is for

Good for

A dozen or so datasets. Files in kilobytes to megabytes. Plans of three to ten steps. One operator. And a hard requirement that every number be traceable.

Would not use for

Answers that live in a warehouse. Untrusted input — the code executor is isolation, not a sandbox. Anything needing durable resume or run history.

Restraint

Where I would not build yet

  • A general workflow engine. The graph is three to six nodes and the scheduler is small. Adopt one when a run spans hours or has human steps that outlive a process.
  • A vector search layer. A catalogued directory is correct until the corpus stops fitting a catalogue.
  • Agent-to-agent negotiation. It adds a failure mode — loops — before it adds a capability.
  • A learned model router. Static routing first; you need the evaluation harness before you can tell whether a router helped.
